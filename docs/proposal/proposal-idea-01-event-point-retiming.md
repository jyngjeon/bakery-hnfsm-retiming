# Group-Based Event-Point Retiming
## 개선안 최종 명세서 | 설계·수학적 근거·구현 규칙·AI 인계

**프로젝트:** 연세대학교 「최적화이론및응용」, Babor et al. (2023) 제과공장 다목적 스케줄링 연구의 재현 및 개선  
**기준일:** 2026-11-04  
**문서 성격:** **무엇을 제안하고 어떻게 구현할지** 설명하는 독립적인 알고리즘 명세서. 실제 수행한 코드·검증 수치·실험 결과는 별도 파일 `02_기존수행작업_검증기록_최종.md`에만 수록한다.  
**현재 채택안:** **오븐 경계 그룹 선별 + 자원 처리순서 변경 허용 + 한 그룹 최선 이동 1회**를 사용하는 Group-Based Event-Point Retiming.

> **한 문장 정의:** NSGA-II가 만든 그룹 우선순서로 HNFSM이 실행 스케줄을 생성한 뒤, 한 제품 그룹의 모든 공정을 같은 시간만큼 평행이동한다. 나머지 그룹의 시간과 전체 자원 배정을 고정하고, 실행가능한 시각의 경계와 오븐 OIDT 함수의 꺾임점만 평가하여 Makespan을 악화시키지 않으면서 OIDT를 개선한다.

## 0. 먼저 구분할 것: 프로젝트 전체 범위와 개선 대상

| 구분 | 합의된 방향 | 완료 여부의 의미 |
|---|---|---|
| **원논문 재현 목표** | **NSGA-II, SPEA2, GDE3, OMOPSO, SMPSO의 5개 모두** 공통 HNFSM에 연결하는 것을 목표로 함 | **5개가 이미 구현됐다는 뜻이 아니다.** 진행하면서 구현·데이터·시간 제약이 확인되면 단계적으로 범위를 줄임 |
| **직접 개선 대상** | **NSGA-II + HNFSM** | 새 Retiming 모듈은 NSGA-II로 평가한 HNFSM 스케줄에 적용하고 기본 NSGA-II와 비교 |
| **공통 평가기** | SPV → 같은 HNFSM → (Makespan, OIDT) | 다른 4개 탐색법을 도입해도 HNFSM을 새로 만들 필요는 없지만, 탐색 연산 및 파라미터 연결은 별도 검증 필요 |
| **주 데이터** | BK15 우선, 이후 BK50 | BK40은 공개 데이터 부재로 직접 재현에서 제외 가능하며 원논문 전체 재현으로 표현하지 않음 |
| **연구 목표** | 재현 가능성 확인 + 개선안의 정확성·품질·추가 비용 검증 | 학술적 최초성이나 전역최적성 주장이 아님 |

**단계적 축소 원칙(계획):** 5개 연결을 우선 시도하되, 반드시 확보할 핵심은 `HNFSM + NSGA-II`와 `NSGA-II + Retiming`의 공정 비교다. 다섯 알고리즘을 모두 연결하는 작업 때문에 개선안 검증이 불가능해지면 SPEA2·OMOPSO 등 주요 비교군을 우선 남기고 나머지를 축소한다. **축소 기준은 실제 기술적 장애나 실험 예산이며, 결과가 불리하다는 이유로 비교군을 임의 제외하지 않는다.**

## 1. 원논문 방법론과 제안 개선안의 관계

### 1.1 원논문의 구조

```text
최적화 알고리즘(NSGA-II / SPEA2 / GDE3 / OMOPSO / SMPSO)
  → 연속형 후보 벡터
  → SPV(Smallest Position Value)로 제품 그룹 우선순서 π 변환
  → HNFSM: 시간·기계·직원·오븐 배정, 실행 스케줄 S 생성
  → (Cmax(S), OIDT(S)) 평가
  → 최적화 알고리즘에 결과 반환 및 반복
```

NSGA-II 등은 **어떤 제품 그룹을 우선 배치할지 탐색**하고, HNFSM은 주어진 우선순서를 입력받아 **제약을 만족하는 상세 생산 스케줄을 생성·평가**한다. 원논문은 5개 다목적 탐색법을 비교해 NSGA-II가 종합적으로 우수하다고 보고했다. **HNFSM이 한 우선순서에 대해 생성한 시간 배치가 국소적으로 최적이라는 보장은 확인되지 않는다.**

**원논문 근거:** `s41598-022-26866-9.pdf` PDF 4~6페이지(Fig. 3·4, M1~M19), 8페이지(SPV·Table 3), 15~16페이지(최적화 알고리즘), 20페이지(Table 5).

### 1.2 우리가 추가하는 것

```text
NSGA-II → SPV → 기존 HNFSM → 상세 스케줄 S
                                  ↓
                  [새 모듈: Event-Point Retiming]
                                  ↓
                      변경된 상세 스케줄 S'
                                  ↓
          독립 실행가능성 검증 + 직접 Cmax/OIDT 재계산
                                  ↓
                       NSGA-II에 fitness 반환
```

**NSGA-II의 선택·교차·변이를 바꾸는 연구가 아니다.** HNFSM의 출력 스케줄을 **후처리(post-processing)**하고, 바뀐 목적함숫값을 NSGA-II에 전달하는 전체 평가 흐름의 개선이다. Retiming은 5개 원논문 탐색법의 재현 여부와 별도로 개발할 수 있다.

## 2. 수학적 정의: 그룹 단위 평행이동

### 2.1 그룹 내부 시간관계

제품 그룹 `g`의 기준 시작시각을 `T_g`, 제품을 `p`, 공정을 `s`라고 하자. 원논문의 Bowl Time(WT)와 No-Wait 관계를 사용하면 그룹 안의 모든 공정은 다음과 같이 쓸 수 있다.

```text
ST[g,p,s] = T_g + a[g,p,s]
CT[g,p,s] = T_g + a[g,p,s] + PT[g,p,s]
a[g,p,s] = WT[g,p] + ∑_{r=1}^{s-1} PT[g,p,r]
```

(그룹 기준 제품의 WT는 0으로 정의.) 그룹의 기준시각을 `T_g → T'_g = T_g + Δ`로 바꾸면, **그룹 내부 모든 공정이 같은 Δ만큼 이동**하여 WT와 No-Wait를 그대로 만족한다. **베이킹 공정 하나만 떼어 움직이는 것은 제안한 방법이 아니다.**

### 2.2 한 번의 국소 이동에서 고정하는 것

- **이동 그룹 `g` 외의 모든 그룹:** 시작·완료시각 완전 고정.
- **모든 공정:** 기존에 배정된 기계, 오븐 구획, 직원 **고정**(이동 그룹도 자원을 다시 선택하지 않음).
- **유일한 변경 변수:** 그룹 `g`의 기준 시작시각 `T_g`.
- **실제 자원 처리순서:** 기계/직원/오븐 충돌이 없으면 기존 작업들의 앞뒤를 넘어서는 배치를 **허용**. 이는 우선순서 π 자체를 다시 인코딩하는 작업이 아니다.
- **비악화 제한:** 이동 이후 `Cmax ≤ 현재 Cmax`.

따라서 한 번의 이동은 **하나의 시간 변수에 대한 제한된 부분문제**이다. 여러 그룹의 연쇄 이동, 직원·기계 재배정, 다른 그룹의 후속 repair는 포함하지 않는다.

### 2.3 실행가능 시작시각 집합 `F_g`

모든 작업 구간은 **반열린 구간 `[start,end)`**, 시간은 기본적으로 **정수 분 단위**다. 그룹 `g`의 작업 `q`가 자원 `r`을 상대구간 `[a_q,b_q)` 동안 사용하고, 다른 그룹의 고정 작업이 동일한 자원을 `[u,v)`에 점유한다고 하자. 서로 겹치지 않으려면:

```text
T_g + b_q ≤ u   OR   T_g + a_q ≥ v
↔ T_g ≤ u-b_q  OR  T_g ≥ v-a_q
```

이 조건을 해당 자원의 다른 그룹 작업 모두와 대조한다. 직원 `l`의 허용 근무구간이 `[L_l,U_l]`라면 직원 배정 작업마다

```text
L_l - a_q ≤ T_g ≤ U_l - b_q
```

를 추가한다. 이 밖에 `T_g ≥ 0`, 모든 공정 종료시각이 기존 Makespan `C₀` 이내라는 조건을 적용한다. **무제한 용량 공정**은 기계 중복검사를 적용하지 않고, 원래 허용된 **동일 그룹 공동 베이킹**은 유지한다.

이 조건들의 교집합은 여러 개의 분리된 정수구간이 될 수 있다.

```text
F_g = [l₁,u₁] ∪ [l₂,u₂] ∪ ... ∪ [l_m,u_m]
```

**검사 기준:** 해당 `T_g`가 `F_g`에 들어도 최종 이동 스케줄을 별도의 독립 제약 검사기에 통과시켜야 한다. 특히 기계·직원 중복·오븐 공동사용·교대시간·누락 공정이 모두 만족되어야 한다.

## 3. OIDT 계산과 Event-Point 탐색의 근거

### 3.1 OIDT 정의를 먼저 고정

원논문 (M2)는 오븐의 최초~최종 사용시간에서 처리시간을 차감하는 형태이고, (M12)는 같은 제품 그룹의 동시 베이킹을 허용한다. 제품별 베이킹 시간을 그대로 합산하면 같은 구획의 겹친 점유시간이 이중 계산될 수 있다.

현재 자체 평가기에서는 각 오븐 구획 `k`에 대해 **실제 점유구간의 합집합 길이** `B_k`를 사용한다.

```text
OIDT_k = (마지막 점유 종료 - 최초 점유 시작) - 점유구간 합집합 길이 B_k
OIDT   = ∑_k OIDT_k
```

비어 있는 구획의 OIDT는 0으로 정의한다. **이것은 팀의 명시적인 구현 해석이지, 원저자의 코드가 동일한 방식이라고 확인된 사실은 아니다.** HNFSM·Retiming·독립 checker가 같은 정의를 사용해야 한다.

### 3.2 한 그룹만 이동하면 OIDT가 구간별 선형이 됨

오븐 구획 `k`에서 이동 그룹의 상대적 최초·최종 베이킹 시각을 `(s_gk,e_gk)`로 두고, **다른 그룹들**의 고정된 최초 시작·마지막 종료를 `(F_k,L_k)`로 두자. 둘 다 이 구획을 사용하는 경우:

```text
OIDT_k(T) = max{L_k, T+e_gk} − min{F_k, T+s_gk} − B_k
```

실행가능한 이동에서는 다른 그룹과의 오븐 구획 점유가 중첩되지 않고, 이동 그룹 내부 상대 점유가 고정되므로 `B_k`는 상수다. 따라서 이 식과 구획별 합계 `OIDT(T)`는 **구간별 선형 함수**다. 꺾이는 후보 시각은

```text
T = F_k - s_gk
T = L_k - e_gk
```

이다. 해당 구획을 이동 그룹만 사용하는 경우 점유 길이와 최초~최종 간격은 함께 이동하므로 OIDT는 상수다. 다른 그룹만 사용하는 구획도 영향이 없다.

### 3.3 정확한 Event-Point 후보 구성

각 실행가능 구간 `[l_i,u_i] ⊂ F_g`마다 **① 양 끝점** `l_i,u_i`, **② 그 구간에 속하는 모든 관련 구획의 OIDT 꺾임점**을 후보로 만든다. 시간 단위가 정수인 BK15에서는 꺾임점도 정수다. 실수시간으로 일반화한다면 꺾임점의 정수 바닥·천장 또는 적절한 이산 후보를 고려한다.

구간별 선형함수는 각 선형 구간의 최솟값을 끝점에서 갖고, 꺾임점은 선형식이 바뀌는 지점이므로 이 유한 후보를 검사하면 **고정 자원 배정·다른 그룹 시간 고정·한 그룹 이동이라는 제한된 문제에서 최적 OIDT를 구할 수 있다.** 여러 그룹의 동시 재배치나 전체 문제의 전역최적성을 뜻하지 않는다.

**동률 처리:** 먼저 OIDT 최소, 동률이면 Makespan 최소, 그다음 `g` 인덱스와 `T_g`의 정해진 순서로 선택해 결정성을 확보한다. 목적함숫값이 둘 다 동일하면 기존 스케줄을 유지한다.

### 3.4 오븐 경계 그룹만 검사하는 가속

각 오븐 구획의 **최초 점유 시작** 또는 **마지막 점유 종료**를 결정하는 그룹을 Retiming 후보로 우선 선별한다. 다른 그룹의 시간과 전체 자원 배정이 고정될 때, 어떤 구획의 내부에만 존재하는 그룹을 이동해도 **총 점유길이와 외곽 경계가 변하지 않으므로 OIDT 감소를 만들어내지 못한다.** 따라서 OIDT 최소화 목적에는 안전한 선별 근거가 있다.

**한계:** 이 선별만으로는 **OIDT가 같으면서 Makespan만 짧아지는 이동**을 모두 찾는다고 보장할 수 없다. 현재 최종 구현 명세는 **OIDT 우선**을 기준으로 한다. Makespan-only 개선까지 확대하려면 Makespan을 결정하는 그룹을 별도 후보로 추가하고 **새로운 실험**으로 평가해야 한다.

### 3.5 개념 예시(실제 BK15 수치 아님)

오븐 구획에 A `[0,20)`, B `[100,120)`, C `[150,170)`이 있으면 점유시간 60분, OIDT는 `170-0-60=110`분이다. **다른 공정·직원·기계의 모든 제약이 허용한다는 가정 아래** A를 `[120,140)`으로 옮기면 최초 점유는 100분, 마지막 종료는 170분, OIDT는 `170-100-60=10`분이 된다. 자원상의 실제 처리순서가 A→B→C에서 B→A→C로 바뀌어도 충돌이 없다면 허용한다. 실제 BK15에서는 A의 모든 공정이 같이 이동해야 하므로 동일 효과를 보장하지 않는다.

## 4. 최종 알고리즘 절차 및 의사코드

**현재 명세는 후보 스케줄 하나당 '가장 좋은 그룹 이동 1회'를 적용한다.** 연속 여러 그룹을 이동하거나 자원 재배정을 결합하는 것은 별도 확장안이며, 이 명세의 검증 범위가 아니다.

```python
# 실행 가능한 완성 코드가 아닌 구현 의사코드. 실제 함수명·자료구조는 첨부 코드를 따를 것.
def evaluate_with_retiming(real_vector):
    order = spv_decode(real_vector)
    base = hnfsm_evaluate(order, policy="shared_batch")
    if base.status != "validated":
        return base                  # 기존 평가 실패 정책과 동일하게 처리

    S = base.schedule
    C0, I0 = objectives_direct(S)    # 구획별 busy-union OIDT 사용
    candidate_groups = oven_boundary_groups(S)
    best = None

    for g in candidate_groups:
        intervals = feasible_integer_intervals(
            S, g, max_makespan=C0,
            fixed_assignments=True,
            allow_resource_order_change=True)
        event_times = interval_endpoints(intervals) | oven_knots(intervals, S, g)

        for T in sorted(event_times):
            S2 = shift_whole_group(S, g, T)  # 다른 그룹과 자원 배정 불변
            if not independent_feasibility_check(S2):
                continue
            C2, I2 = objectives_direct(S2)    # 실제 수정한 스케줄에서 직접 계산
            if C2 <= C0 and I2 <= I0 and (C2 < C0 or I2 < I0):
                best = lexicographic_best(best, (I2, C2, g, T, S2))

    if best is None:
        return base
    return validated_result_from_modified_schedule(best.schedule)
```

**구현자에게 중요한 네 가지 규칙:** (1) `evaluate(order)`를 Retiming 후 다시 부르면 원래 HNFSM이 스케줄을 재생성하므로 이동 효과가 사라진다. (2) 변경된 상세 스케줄에서 직접 목적값을 계산하고 독립 checker를 통과시킨다. (3) 이득이 없거나 실패한 후보는 원래 스케줄을 반환한다. (4) 같은 입력·동률에는 같은 결과를 반환할 결정적인 탐색 순서를 사용한다.

## 5. 평가·확장·비교 계획(구현 명세에 필요한 범위만)

### 5.1 원논문 5개 알고리즘의 공통 평가기

공통 인터페이스는 `candidate_vector → SPV → HNFSM → Cmax/OIDT`이다. 5개 최적화 알고리즘은 **각자 다른 탐색 메커니즘으로 같은 평가기를 호출**하도록 연결한다. 그러나 **이미 연결된 것으로 기록하지 말 것**. PSO 계열과 GA/DE 계열의 표현·상태갱신·파라미터를 별도로 검토해야 하며, 원논문의 정확한 라이브러리는 확인되지 않았다. jMetalPy 등의 사용은 후보일 뿐 원저자의 사용이 입증된 것은 아니다.

필수 기준 비교는 **기존 `NSGA-II + HNFSM`(B0) 대 `NSGA-II + HNFSM + Retiming`(P1)**이다. 다른 4개 알고리즘은 원논문 재현의 비교군이며 Retiming을 모두 적용할 필요는 없다. 확보되면 개선 NSGA-II와 다른 탐색법의 결과도 참고 비교할 수 있지만, 그것만으로 다른 방법에 Retiming을 결합했을 때의 우수성을 주장하지 않는다.

### 5.2 검증 항목 및 비교의 공정성

- **부분문제 정확성:** 손으로 푸는 소형 사례 및 가능한 정수 시각 전수탐색과 Event Point 결과를 대조한다.
- **실행가능성:** WT·No-Wait, 전체 공정 포함 여부, 기계/직원/오븐 비중첩, 근무시간, 배정 불변을 독립 checker로 검증한다.
- **Ablation:** 자원 순서 변경 허용/고정, 경계 그룹만/전체 그룹을 비교한다.
- **전체 성능:** 동일한 BK 인스턴스·디코더·목적함수·가능한 한 같은 초기 후보/시드에서 Hypervolume(HV), 최소 Makespan, 최소 OIDT, 실패율을 비교한다.
- **계산비용:** 동일 HNFSM 평가 횟수와 **동일 실행시간**을 모두 보고한다. 추가 Retiming 시간은 공짜가 아니다.
- **일반화:** BK15에서 방법 검증 후 BK50의 데이터 불일치를 해결하고 확장한다. BK40 비공개는 제한사항으로 적는다.
- **통계:** 파일럿보다 많은 독립 시드를 사용하고 평균·중앙값·효과 크기·신뢰구간·시드별 승패를 보고한다.

**중요:** 단일 Retiming이 Pareto 비악화여도, 새로운 평가값에 의해 NSGA-II의 탐색 경로가 바뀌므로 **최종 전체 Hypervolume의 우위는 보장되지 않는다.**

## 6. 학술적 표현과 선행연구의 경계

No-Wait 작업의 시작시각 이동, 최적 작업 삽입, 시간구간 기반 탐색과 유사한 발상은 선행연구에 존재한다. 따라서 **'Event Point를 최초로 발명했다'**, **'No-Wait 재배치를 학계 최초로 제안했다'**, **'모든 스케줄에서 성능 향상'** 같은 주장은 하지 않는다. 이 수업 프로젝트의 기여는 **Babor의 WT·직원 교대·오븐 공동사용 제약과 OIDT 목표에 맞춘 구체적 후처리, 엄밀한 검증과 공정한 성능 비교**에 있다.

원논문 및 관련 연구(추가 인용 전 서지정보를 재확인할 것):

- Babor et al. (2023), *Modeling and optimization of bakery production scheduling to minimize makespan and oven idle time*, *Scientific Reports* 13:235, DOI: 10.1038/s41598-022-26866-9.
- Bürgy & Gröflin (2013/2017), No-Wait Job Shop의 최적 작업 삽입 및 regular 목적함수 관련 연구.
- Xu et al. (2021), No-Wait 작업 순서와 시간 배치 분리 연구, *Algorithms* 14:145, DOI: 10.3390/a14050145.
- Deng et al. (2024), No-Wait Job Shop의 Left–Right Shift, DOI: 10.1016/j.eswa.2023.122112.
